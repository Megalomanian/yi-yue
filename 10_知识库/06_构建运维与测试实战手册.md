## 一、线一：课程文档与图表构建流水线（`06_构建脚本/`）

所有命令均在仓库根目录 `yi-yue/` 下打开 PowerShell 执行。

### 1.1 常用改稿与重生成命令

```powershell
# 1. 修改开题报告或 SRS 正文后（编辑 01_开题报告/开题报告-正文.md 或 03_SRS/SRS-正文.md）
python 06_构建脚本/md2docx.py
powershell -File 06_构建脚本/docx2pdf.ps1 -Docx "01_开题报告/项目开题报告.docx" -Pdf "07_交付/项目开题报告.pdf"
powershell -File 06_构建脚本/docx2pdf.ps1 -Docx "03_SRS/软件需求规格说明书.docx" -Pdf "07_交付/软件需求规格说明书.pdf"

# 2. 修改开题答辩 PPT 后
python 06_构建脚本/build_ppt.py
powershell -File 06_构建脚本/pptx2pdf.ps1 -In "02_答辩PPT/开题答辩.pptx" -Out "07_交付/开题答辩.pdf"

# 3. 修改 09_答辩稿/*.md 后重新生成 7 份个人与总答辩稿 Word
python 06_构建脚本/build_scripts_pdf.py
powershell -File 06_构建脚本/batch_docx2pdf.ps1

# 4. 每次改稿后必跑：机械合规与格式自检（刷新 08_自检报告.md）
python 06_构建脚本/qa.py
```

### 1.2 `06_构建脚本/` 脚本职责速查
- **排版导出**：`md2docx.py`（生成带标准封面、变更历史、自动 TOC 目录域、页眉页脚、行不跨页表格的 Word）、`build_ppt.py`（生成 15 页答辩 PPT 含演讲者备注）、`build_scripts_pdf.py`（生成需求评审答辩稿 Word）、`docx2pdf.ps1` / `pptx2pdf.ps1` / `batch_docx2pdf.ps1`（调用本机 Office COM 导出精确版式 PDF）。
- **图表代码化生成**：`draw_usecase.py`（用例图）、`draw_ui.py`（4 张移动端与 PC 原型图）、`draw_ppt_figs.py`（架构图与甘特图）、`draw_deck_assets.py`（答辩高清配图），以及 `tools/plantuml.jar`（渲染 `04_图表/plantuml/*.puml` 顺序图、类图、状态图）。
- **合规清洗与质检**：`qa.py`（禁用词、校名越界、PDF ≤ 5MB、PPT ≤ 6 行 & ≥ 20pt、章节完整性核对）、`export_ai_log.py` / `tidy_ai_log.py`（导出与整理 `05_AI记录/`）。

> **注意**：`01_开题报告/开题报告-正文.md` 与 `03_SRS/SRS-正文.md` 中的 `[[FIG:图x-x]]` 是插图锚点占位符，**切勿删除**；紧随其下一行的文本会自动渲染为图题。

## 二、线二：全栈系统本地开发、测试与压测（`system/`）

所有命令在 `yi-yue/system/` 目录下打开 PowerShell 执行。

### 2.1 环境依赖与快速启停
- **前置环境**：JDK 21、Maven 3.9、Node.js 22/24、Chrome（或 Edge）。脚本 `scripts/environment.ps1` 会优先探测 `system/.tools/` 内置的便携版 JDK/Maven，若在新机器克隆仓库（`.tools/` 被 `.gitignore` 忽略），会自动回退使用系统 `JAVA_HOME` 与 `PATH` 中的 `java` / `mvn` / `node`。

```powershell
cd system

# 1. 完整构建与单测/集成测试（后端 mvn verify + JaCoCo 覆盖率 + 前端 npm ci + vitest + vite build）
./scripts/build.ps1

# 2. 后台启动本地演示服务（自动复制 JAR 到 data/runtime/ 防 Windows 文件锁占用，并轮询健康检查）
./scripts/start.ps1

# 3. 停止本地前后端进程（按命令行目录特征安全匹配，不误杀其他 Java/Node 进程，保留 H2 数据）
./scripts/stop.ps1
```

启动成功后访问入口：
- **Web 工作空间**：`http://localhost:5173`
- **后端健康检查**：`http://127.0.0.1:8080/actuator/health`
- **Swagger UI 在线接口文档**：`http://127.0.0.1:8080/swagger-ui/index.html`
- **OpenAPI 3.0 JSON**：`http://127.0.0.1:8080/v3/api-docs`

## 三、线三：Docker Compose 生产部署与备份恢复

### 3.1 容器化部署（2 核 4G 起步）
`system/compose.yml` 编排了 5 个固定版本的服务，内存配额受控（总计约 `2.8 GB`）：
- `mysql`（`mysql:8.0.41`，限额 `768m`）
- `redis`（`redis:7.4.2-alpine`，开启 AOF 与密码，限额 `192m`）
- `minio`（`minio:RELEASE.2025-02-07T23-21-09Z`，限额 `512m`）
- `backend`（Spring Boot 运行容器，强制开启 `REDIS_LOCK=true`、`STORAGE=minio`、`DEMO_MODE=false`，限额 `1200m`）
- `web`（Nginx 静态资源与 `/api` 反代，仅绑定宿主机 `127.0.0.1:8088`，由学校前置网关终止 HTTPS，限额 `128m`）

```powershell
cd system
Copy-Item .env.example .env
# 编辑 .env：配置强随机 DB_PASSWORD、DB_ROOT_PASSWORD、REDIS_PASSWORD、MINIO_PASSWORD、
# 至少 32 字节 JWT_SECRET、高熵 ENCRYPTION_KEY 以及至少 16 位的 BOOTSTRAP_PASSWORD
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build
```

> **安全铁律**：`ENCRYPTION_KEY` 是解密数据库中联系方式、经费卡、实名审核材料及 MinIO 中检测报告的唯一主密钥，**一旦丢失或覆盖无法恢复历史密文**，必须离线异地备份！

### 3.2 加密备份与隔离恢复演练（`scripts/backup.sh`）
- **备份**：Linux 服务器配置 `BACKUP_RECIPIENT`（GPG 公钥指纹）后执行 `scripts/backup.sh`，通过 `mysqldump --single-transaction` 获取数据库一致性快照，连同对象存储文件打包并用 GPG 公钥加密落盘。
- **恢复演练标准 SOP**：停止写入 → GPG 私钥解密 → **导入独立隔离测试库（严禁未验证直接覆盖生产库）** → 还原 MinIO 对象 → 配置同源 `ENCRYPTION_KEY` 启动同版本后端 → 核验 `/actuator/health`、登录、报告下载 `SHA-256` 校验及账单总额 → 记录 RTO 耗时。

## 四、常见故障排障速查表（Troubleshooting SOP）

| 现象 / 报错 | 根因定位 | 解决步骤 |
|---|---|---|
| `start.ps1` 报「端口 8080 或 5173 已被使用」 | 上次实例已在运行，或被本机其他程序占用 | 若仪约已启动直接访问 `http://localhost:5173`；否则先执行 `./scripts/stop.ps1` 再执行 `./scripts/start.ps1` |
| Windows 下重新 `mvn package` 时报无法删除 `target/*.jar` | 直接运行 `target/` 下的 JAR 会被 JVM 锁死文件句柄 | 始终使用 `./scripts/start.ps1`（它会将 JAR 复制为 `data/runtime/instrumenthub.jar` 运行，不锁 `target/`） |
| 校外账号登录后看不到仪器列表或报 `403 账号正在等待实名审核` | 新注册 `EXTERNAL` 用户默认 `approved=false` | 切换登录 `admin` → 进入左侧「用户审核」→ 点击核验实名材料并点击「批准」 |
| 提交预约报 `403 上机资质未取得、已过期或信用分低于60` | 缺少对应仪器有效 `qualification` 或 `credit < 60` | 登录送样人进入「培训与资质」报名 → 切 `manager` 初审通过 → 切回送样人参加 5 题考试（答案下标：`2, 1, 2, 3, 1`，即第2/1/2/3/1项，代码 0-based 为 `[1,0,1,2,0]`）拿满 100 分获证 |
| 提交或签到报 `409` | 时段已被抢占、状态已变更、不在 `[start_at, start_at+15m]` 窗口或输错仪器 ID | 刷新页面查看最新预约状态；网页签到时确认输入的是数字仪器主键 ID（如 `1` 对应 `IY-001`） |
| 预约报 `503 预约锁服务暂不可用` | 开启了 `REDIS_LOCK=true` 但 Redis 实例不可达 | 检查 Redis 容器状态与密码；本地无 Redis 演示时保持 `REDIS_LOCK=false` |
| 微信小程序真机预览报网络请求失败 | `miniprogram/app.js` 默认 `baseUrl` 为 `http://127.0.0.1:8080/api`，真机上的 `127.0.0.1` 指向手机自身 | 电脑演示用微信开发者工具模拟器；真机联调需改为电脑局域网 IP（开启开发工具「不校验合法域名」）或部署 HTTPS 域名 |
| 启动报 `IllegalStateException: 生产模式必须配置 JWT_SECRET...` | `DEMO_MODE=false` 时仍使用了默认的 `local-demo*` 密钥或 `BOOTSTRAP_PASSWORD` 不足 16 位 | 按 `.env.example` 为生产环境变量配置正式随机长密钥 |
