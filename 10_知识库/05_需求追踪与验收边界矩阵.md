## 三、SRS 设计约定 vs 当前代码实现的 9 项诚实差异

在课程答辩或撰写最终《系统总结报告》时，主动说明以下架构演进与边界体现了严谨的工程实事求是态度：

1. **MyBatis 仓储组织形式**：SRS 约定按领域拆分为多个独立 Mapper XML；当前代码采用 `StoreMapper` + `SqlMapper` 参数化 SQL 集中封装，保持单包紧凑，后续可在不改 REST 契约的前提下拆分。
2. **REST 响应包络格式**：SRS 早期约定统一 `{code, message, data}` 外壳；当前实现遵循标准资源型 REST 风格——成功直接返回资源对象/数组与 `200 OK`，异常统一返回 `{"message": "...", "status": 4xx/5xx}` 及对应 HTTP 状态码（以 `system/docs/openapi.json` 为准）。
3. **移动端双轨共存**：SRS 将 Vue/Vant 与原生微信小程序混在一处描述；当前工程同时提供了 **Vue + Vant 响应式移动网页** 与 **`system/miniprogram/` 原生微信小程序** 两套客户端，共用同一套后端 API。
4. **候补队列存储介质**：SRS 设想使用 Redis Sorted Set 存候补队列；当前改为数据库 `submission_sequence` 表持久化提交序号，Redis 仅承担生产分布式互斥锁，好处是进程或缓存重启绝不丢失候补排队状态。
5. **多口径例外清单**：当前统计报表按 `50万 / 20万 / 40万` 三个资产原值阈值精确过滤；对于「资产不足 40 万但被人工特批列入校内共享清单」的例外标记开关，留作二期配置项扩展。
6. **跨周期账单收入归属**：统计报表中的机时分子已精确按统计窗口 `[from, to]` 截断交集，但账单收入 `revenue` 当前按整张费用单归入相交周期，未按秒拆分跨月账单金额。
7. **大体积原始数据分片**：当前单次报告上传上限为 `20 MB`（覆盖常规 PDF 报告与中小型图谱压缩包）；电镜超大原始图像序列的分片断点续传留作二期扩展。
8. **外部网关物理联调**：校内统一认证（SSO）、微信模板消息与既有平台机时回写均已实现完整 HTTP 网关契约、超时控制与指数退避重试测试，但未接入学校真实生产密钥与内网网关。
9. **本地容器运行时验证**：`compose.yml` 已通过语法与配置校验，因当前开发机 Docker Desktop 引擎未启动，本地验收基于 H2（MySQL 兼容模式）+ 本地加密文件存储完成。
