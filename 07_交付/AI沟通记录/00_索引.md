# AI 沟通记录 · 索引

本目录记录本项目**全部 AI 协作过程**，由 OpenCode 本地会话库（`opencode.db`）直接导出为 **JSONL 日志**，未经改写，保留原始时间戳、模型标识、工具调用与令牌用量。

- 使用模型：`workbuddy/deepseek-v4.1-flash`（主会话 + 6 个并行子代理，同一模型）
- 导出格式：JSONL（每行一条完整 JSON 对象，UTF-8 无 BOM），便于程序解析，也便于逐行核对
- 导出一致性：会话 ID 可在 OpenCode 子会话面板中逐一对应，见 `09_截图清单.md`

## 二、记录结构

每行一个 JSON 对象，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | int | 会话内递增序号 |
| `ts` | string | ISO 8601 时间戳，毫秒精度 |
| `session` | string | 会话 ID（`ses_` 开头） |
| `parent` | string \| null | 父会话 ID；主会话为 `null` |
| `role` | string | `user`（人工指令 / 子代理任务书）或 `assistant`（AI 回复） |
| `agent` | string | 仅 assistant 有，`build` 或 `general` |
| `model` | object | 仅 assistant 有：`{provider, id, variant}` |
| `parts` | array | 消息内容片段，见下 |
| `tokens` | object | 仅 assistant 有：`input / output / reasoning / cache_read / cache_write` |
| `cost` | number | 仅 assistant 有：本次调用费用 |

`parts` 支持两种片段：

```json
{"type": "text", "text": "……"}
{"type": "tool", "name": "shell",
 "input": {"command": "python 06_构建脚本/qa.py"},
 "output": "……", "output_len": 3210, "output_truncated": true}
```

一条实际记录（格式化后）：

```json
{
  "seq": 1,
  "ts": "2026-10-28T08:35:43.061",
  "session": "ses_e8010d5bfffeXiPj9KKrtjwQwS",
  "parent": null,
  "role": "user",
  "parts": [{"type": "text", "text": "阅读文件内容\nAttached file: ..."}]
}
```

## 三、如何查看

**方式一：用附带的阅读脚本（推荐）**

```powershell
python 06_构建脚本/read_ai_log.py                 # 列出全部会话
python 06_构建脚本/read_ai_log.py 01              # 以可读形式打印主会话
python 06_构建脚本/read_ai_log.py 05 --tools      # 连同工具调用一起打印
```

**方式二：直接打开**

`.jsonl` 是纯文本，记事本、VS Code 都能直接打开，每行一条记录。

**方式三：命令过滤**（Windows 上可用 `Get-Content`）

```powershell
# 只看人工指令
Get-Content 05_AI记录\01_主会话.jsonl | Select-String '"role":"user"'
# 只看调用了哪些工具
Get-Content 05_AI记录\01_主会话.jsonl | Select-String '"type":"tool"'
```

## 四、导出说明

1. 时间戳为会话库原始记录值，未做对齐、补写或修饰。
2. **不导出 `reasoning`**（模型内部推理过程），只导出可核对的对外内容：人工指令、AI 回复、工具调用与输出。
3. 工具输出超长部分已截断，每段保留前 400 字符，并在 `output_len` 中标注原文长度、`output_truncated` 标注是否截断。
4. 子代理 `.jsonl` 中的 `role: user` 记录即主会话下发给该子代理的任务书全文。
5. 本记录不含任何虚构对话。AI 未参与的内容（如真实调研数据）在 `00_事实源/待人工核实清单.md` 中单独列出。

## 五、协作流程

```
人工：提出任务 → AI 给出三个候选选题与 4 个确认项
  │
人工：拍板选题 A + 全套交付 + 6 人 + 真实校名          ← 决策点 1、2
  │
AI：写事实卡 v1 → 并行拉起 4 个子代理（A1 报告 / A2 建模 / A3 SRS / A4 核验）
  │
A4 核出：学校已有仪器共享系统，原立论与公开事实冲突      ← 关键转折
  │
人工：否决原叙事，改为补缺口定位，只保留已核实数据        ← 决策点 5
  │
AI：事实卡升 v2 → 并行拉起 2 个子代理回改（R1 / R2）
  │
AI：图表返工、文档工程、PPT 重做、自检
  │
人工：确认 AI 记录按真实原文导出，不做虚构补写          ← 决策点 11
  │
人工：要求删除全部一手调研内容，改为文献与竞品调研        ← 决策点 12
```
